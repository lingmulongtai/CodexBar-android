# CodexBar for Android v0.16.3

This recovery patch fixes release-only initialization of WorkManager one-time tasks. Install **CodexBar-Android-v0.16.3.apk** over the existing app; version code **48** keeps the pinned production signer and existing data.

**Recovery from v0.16.1 or v0.16.2:** their in-app updater cannot start the work that would download its own fix. Download this APK using the GitHub app and install it once over the existing app. Do not uninstall CodexBar or clear its data. Android still asks for installation approval.

## What failed and what changed

- The optimized v0.16.1/v0.16.2 APKs retained `OverwritingInputMerger` but removed its public no-argument constructor. WorkManager creates it reflectively. Pressing Download therefore failed before HTTP transfer with `NoSuchMethodException`, displayed as “A verified update is unavailable”. This was reproduced using the actual production-signed v0.16.1 app and its real update dialog.
- The app now explicitly retains input-merger constructors during optimization. APK hash, package/version and signer validation remain enforced; this patch does not bypass verification.
- The release pipeline inspects the actual minified DEX and refuses publication if this constructor is absent. Its parser tests reject the shape of both broken published APKs.
- A manually dispatched, non-publishing verification mode builds the same optimized app as version 0.0.0/code1 with the production signer. This allows the real UI to download and verify the already-public stable APK before release acceptance. Candidate version/signature, DEX and startup checks precede upload; candidates never enter GitHub Releases.

Continuous pages, per-screen provider order, haptics, icons, authorizations, saved connections and acquisition modes retain their existing behavior. Companion packages have matching release metadata; no companion runtime or dependency was changed.

## Verification and limits

Acceptance requires the complete Android checks, parser tests, rejection of the broken production APK, a minified signed candidate's real update path, and the normal signed release pipeline. The six bundled screenshots are explicitly unchanged v0.16.2 UI references, not updater-success evidence. See the [updater guide](https://github.com/lingmulongtai/CodexBar-android/blob/v0.16.3/docs/in-app-updates.md) and [release workflow](https://github.com/lingmulongtai/CodexBar-android/actions/workflows/release.yml).

This bug was missed by the earlier debug Worker proof and by production startup/ADB overwrite checks, which did not exercise input merging in the optimized production update path. Native emulator evidence is kept separate from physical-device acceptance.

Read-only upstream main checked at `1811d1fe032fd4a80240fd6bc5d04cee649a0afb`; no upstream-only changes required incorporation or deferral.
