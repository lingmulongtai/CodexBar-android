# CodexBar for Android v0.16.1

This patch replaces the browser download handoff with an in-app APK updater. Install **CodexBar-Android-v0.16.1.apk** over the existing app; version code **46** retains the pinned production signing identity and existing app data.

**First update:** v0.16.0 still uses the old browser handoff. If that browser download stalls, download this v0.16.1 APK through the GitHub app and install it once. Subsequent updates can download inside CodexBar.

- **In-app download:** both the startup update prompt and Settings → About CodexBar display transferred bytes and progress. Close the prompt to continue in the background and find the same request in Settings.
- **Clear completion states:** waiting, downloading, checking, ready, cancelled and failed are distinct. Cancellation closes the connection and removes the partial file. A three-minute transfer deadline and a 30-second read timeout produce a retry action instead of an endless download. Interrupted transfers restart from zero.
- **Verified installation:** expected size, SHA-256, package ID, selected version, increasing version code and the installed signing identity must match. Verification runs again before Android's installer receives temporary read access to the private APK. The installer and any first-time install-source permission still require user confirmation.
- **Saved download recovery:** verified downloads survive app process recreation. Install names the saved version; a newer available release can replace an older saved APK. Failed installer preparation offers download retry. Already-installed versions no longer leave a stale Install action.

Existing Dev settings, GitHub authorization, saved connections, widgets and acquisition modes retain their behavior. Shared PC history, spend and remote settings still require Windows v0.71.0 or later. See the [in-app update guide](https://github.com/lingmulongtai/CodexBar-android/blob/v0.16.1/docs/in-app-updates.md).

## Verification and limits

Local validation completed 514 tests: 512 passed and two explicit opt-in Windows interoperability tests were skipped. Debug lint and APK assembly passed. On a disposable API 36.1 emulator, the actual public v0.16.0 APK transferred all 6,744,190 bytes, matched GitHub's SHA-256 and parsed as the expected package/version. The production foreground worker also completed its download and verification, then correctly rejected the non-newer APK.

Controlled debug fixtures separately exercised progress, cancellation, error/retry presentation, READY recovery after process restart, install-source permission and Android's actual package installer. A debug-signed test update preserved a private marker after installation. This does not claim a production-signed self-update or physical-device verification. The signed release workflow builds and smoke-tests the APK, checks the pinned signer, and publishes checksums, SBOMs and build provenance.

The reported Vivaldi stall was not assigned a confirmed browser root cause; this patch removes the browser dependency. Android can defer background work. Development builds with a different signing key cannot be overwritten by the production APK.

Read-only upstream main checked at `1811d1fe032fd4a80240fd6bc5d04cee649a0afb`; no upstream-only changes needed incorporation or deferral.
