# CodexBar for Android v0.16.4

This patch improves tablet, landscape and resizable-window layouts. Install
**CodexBar-Android-v0.16.4.apk** over the existing app; version code **49** retains
the pinned production signer and existing data.

- **Full-width headers:** Connections and Settings no longer constrain the glass
  header itself to 840 dp. The glass spans the usable window and only the inner
  content has a reading-width limit. Short landscape windows compact header
  spacing while keeping controls and typography readable.
- **Usage overview and details:** a persistent detail pane appears only when
  width, height and font scale allow it. The overview keeps the remaining space;
  medium and short windows retain the existing detail sheet. Quota and Trends
  cards include padding and gaps when selecting their column count.
- **Adaptive forms:** Settings and Connections use one or two readable columns.
  Expanded connection forms use the full content width and stay visible when
  their grid span changes. Settings sections remain
  composed across column changes and scrolling, retaining in-progress form state
  and section-owned work within the activity.
- **Resizing and input:** horizontal safe insets protect side cutouts. The pinned
  header stays visible above the keyboard instead of being panned offscreen.
  Keyboard input does not put the floating dock over fields, and explicit navigation
  clears focus and dismisses the keyboard. The fixed pager viewport, settings
  return paths, provider order and GitHub widget preferences remain intact.

Recovery from v0.16.1/v0.16.2 still requires one manual APK overwrite using the
GitHub app. Do not uninstall or clear data. The v0.16.3 WorkManager constructor
fix, APK/hash/signer verification and in-app updater remain enforced. Shared PC
history, spend and remote settings require Windows v0.71.0 or later. Companion
archives have matching version metadata; their runtime and dependencies did not
change.

## Screens and verification

The bundled images are real API 35 emulator captures of debug v0.16.4/code49
with synthetic quota/GitHub data. The completed matrix has **12 cases and 60
screen captures**. English navigation, every tab, full-width
headers and Settings return were checked at 360×800, 600×900, 840×720, 800×1280,
1280×800, 1600×1000 and 900×400 dp. Japanese text at 1.3× font scale was also
checked at 840×720 and 1280×800. Japanese portrait/landscape and light appearance
were checked separately. Focused checks also cover the keyboard, expanded
connection forms and cross-column drag ordering. See the [adaptive layout record](https://github.com/lingmulongtai/CodexBar-android/blob/v0.16.4/docs/adaptive-tablet-layout.md)
for the completed verification scope and emulator diagnosis.

Local Windows emulator processes terminated with host-native access violations
(`0xc0000005`) on the software OpenGL ES/SwiftShader path in both 36.2.11 and
37.2.13. Follow-up verification uses an isolated official emulator 37.2.13 with
the host NVIDIA GPU; the installed SDK remains unchanged. Startup also waits for
System UI before sending input. The capture driver rejects ANR overlays/events,
waits for settled UI and records the installed APK identity, instead of accepting
a screenshot after a fixed delay. The native crash's exact faulting instruction
is not attributed to a specific upstream fix.

Publication requires the full CI checks and normal signed-release workflow,
including minified DEX/WorkManager inspection, the pinned signer, emulator startup,
checksums, SBOMs and provenance. Emulator screen checks do not establish physical
fold/hinge posture, OEM cutout behavior or the feel of haptics on hardware.
