# CodexBar for Android v0.13.3

This release refines the Liquid Glass experience across the Android app and hardens its signed-release startup checks after emulator disconnects interrupted the preceding publication attempts. Install **CodexBar-Android-v0.13.3.apk** over the existing app; Android version code **42** preserves the production signing identity and existing settings.

- **New app icon:** a blue, glass-inspired CodexBar mark is used for standard and themed Android launcher icons.
- **Glass throughout:** a black-to-transparent header lets content scroll underneath, with Glisse-inspired switches, sliders, segmented controls, buttons and service details.
- **Smoother navigation and ordering:** page content slides horizontally while the header smoothly changes height; ordering controls animate when entering and leaving reorder mode.
- **Daily photography:** portrait-oriented Unsplash photos are preferred, with attribution retained. A previously loaded image remains available when a refresh fails.
- **Settings and connections:** a translucent connection summary matches the rest of the interface. Settings now shows the app version, project links, release page and an explicit update check.
- Existing connections, Android and Windows acquisition modes, widgets and companion workflows are preserved. Shared PC history, spend and remote settings require Windows v0.71.0 or later.

## Verification and limits

The owner accepted the Liquid Glass design on a physical Android device using a separate preview build with synthetic usage data. Local debug assembly, unit tests and lint cover this release; the production-signed APK is built and smoke-tested by the release workflow, which also checks the pinned signer and publishes checksums, SBOMs and provenance attestations after all release gates pass. A production-signed v0.13.2 candidate with the same screen and navigation code was installed on a physical Android device; the owner confirmed the usage, connections and settings screens worked. The final v0.13.3 APK and older Android versions still require their own device verification.

Read-only upstream main was checked at `1811d1fe032fd4a80240fd6bc5d04cee649a0afb`; no upstream-only commits required incorporation or deferral.
