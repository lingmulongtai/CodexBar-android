# CodexBar for Android v0.9.1

This patch focuses on widgets that remain on Loading, narrow Niagara Launcher layouts, and lock-screen notification privacy. No account, credential, or database migration is required.

## Widget rendering

- Publish a simple native view of saved quota before composing the full widget. Rendering does not wait for a provider request or for WorkManager to start a Glance session.
- Wait for actual RemoteViews composition, with a four-second deadline, rather than treating a queued Glance update as a successful render. If composition fails or times out, keep the cached view and retry in the background.
- Serialize updates for each widget and read the latest launcher dimensions for every render, including rapid resize events.
- Add a diagnostics card to widget settings with the widget ID, requested size, update time, render stage, and error category. `sent` means Android accepted the view; it is not a claim that every launcher drew it successfully. Tap a basic fallback view to open these diagnostics.
- Use compact quota rows below 180dp height or 240dp width. A 40dp-high widget shows one provider; 60dp can show two. Minimum resize dimensions are now 140 x 40dp. Displayed providers follow the saved selection order.
- Use Glance-supported day/night colors so quota numbers remain readable when the launcher theme differs from the app theme.

## Lock-screen notifications and Now Bar

- Android 16 notifications now explicitly use PUBLIC visibility when lock-screen redaction is off and PRIVATE visibility with a generic public version when it is on.
- Privacy changes immediately republish existing notifications and widgets, without another network refresh. Notification actions and countdowns survive a privacy change after the app process restarts.
- Settings explains the system-level restriction and provides a shortcut to the live-monitoring notification channel.

To show quota before unlocking, turn off **Redact lock-screen notifications** and **Redact notification quota details** in CodexBar's Privacy settings, then allow notification content in Android / One UI's lock-screen settings. Android and Samsung retain final control over lock-screen and Now Bar visibility; the app cannot override a system restriction. See [Android notification visibility](https://developer.android.com/reference/android/app/Notification#VISIBILITY_PUBLIC).

## Verification and limits

- Strict dependency verification, the debug build, unit tests, and Android lint passed.
- A real AppWidgetHost rendered ten combinations of size, legacy size options, and privacy state, including 320 x 40dp, 320 x 60dp, and 140 x 60dp. The checks require quota text to be fully visible, not merely present in a view tree.
- Niagara Launcher v1.16.29 on an Android 16.1 emulator displayed Codex and Copilot quota in a widget resized with Niagara's own controls. Cached quota also rendered with Wi-Fi and mobile data disabled.
- Actual Android 16 notification objects were checked for both visibility choices and a cold-instance hide/show cycle preserving details and actions.
- Captures use demo quotas only. Samsung hardware, the user's exact Niagara configuration, fingerprint-unlock transitions, and One UI Now Bar presentation still need device verification.

## Install or update

Download `app-release.apk` and install it over v0.9.0 without uninstalling. Existing connections and widget configuration are retained. If an existing widget still shows Loading, open its settings, save the selected providers again, and inspect the diagnostics card. For a thin two-provider layout, allow at least 60dp of content height; launcher padding may require a little more space.

Companion packages carry the same release version for distribution consistency; their implementation and protocols are unchanged.
